# mcp-go-next v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship mcp-go-next v0.1: a stateless Go library for MCP revision 2026-07-28 built for servers with many tools, with toolsets, a cached tool list, principals and owned handles, a resilient client, stdio and Streamable HTTP with CORS, and a tested cookbook, passing every core conformance scenario.

**Architecture:** `protocol` holds wire types, `jsonrpc` holds framing, `jsonschema` infers and validates schemas. The root package `mcp` is a `Handler` based server with a copy-on-write registry, a client `Conn` over a one-call-per-request `Transport`, and `HandleMessage`, which turns a message into a response for any transport. Transports live in `transport/stdio` and `transport/streamable` and hold no protocol logic.

**Tech Stack:** The latest Go release (1.27.4), standard library only. CI on GitHub Actions with golangci-lint, govulncheck and `npx @modelcontextprotocol/conformance`.

**Spec:** `docs/design.md`. Later phases: `docs/plans/roadmap.md`.

## Global Constraints

- Module `github.com/raven-clown/mcp-go-next`, `go 1.27.4` in `go.mod` (the latest Go release; bump it with each new release). Every CI job reads the version from `go.mod`. No `require` lines in the core `go.mod`, tests included.
- Protocol version constant `"2026-07-28"`. The server supports only that version in v0.1.
- `jsonrpc` imports only the standard library. `protocol` imports only the standard library. Transports import `mcp`; `mcp` never imports a transport.
- Library packages never print and never touch `os.Stdout` or `os.Stderr`.
- Tests are written first. No network outside `httptest`, no bare `time.Sleep` (poll with a deadline instead), every test passes on Windows. Use `filepath` for paths.
- No `exec` of any program except the test binary itself (helper process pattern) in `transport/stdio` tests.
- No em-dashes anywhere. Code comments short and only about why.
- Never mention AI, assistants or code generation in code, comments, docs, commits or PRs. No `Co-Authored-By` or `Generated with` trailers.
- Conventional Commits. Stage files by name, never `git add -A` or `git add .`.
- The repository `raven-clown/mcp-go-next` already exists with README, LICENSE, NOTICE and docs on `main`. The local folder is `D:\workspace\mcp-go-next`. Every task after that runs on its own branch (`feat/<topic>`, `fix/<topic>`, `ci/<topic>`, `docs/<topic>` or `chore/<topic>`) and lands through a pull request. The PR gets labels, the `v0.1` milestone, the assignee `raven-clown`, and a link to its issue on the Project. It is squash merged with `--subject "<pr title> (#<n>)" --body ""` after CI is green. The maintainer says yes once at the start of execution to this push-and-PR flow. Anything outside it (new repositories, releases, settings changes beyond Task 1) needs its own yes.
- Coverage of the whole module stays at 80% or more from Task 6 on.
- On Windows without a C compiler run `go test ./...`; CI runs `-race`.

## Review Focus

- Request IDs that are large or fractional numbers (`9007199254740993`, `1.0`) come back in the response byte for byte. Test: Task 2 `TestIDPreservesBytes`, Task 16 `TestServeEchoesOddIDs`.
- `tools/call` with `arguments` missing or `null` is treated as `{}` and then validated, so a missing required field gives an `isError` result naming the field, never a panic or a protocol error. Test: Task 8 `TestCallToolNullArguments`.
- A handler that ignores its context while stdin hits EOF must not hang `stdio.Serve` forever: after the drain timeout contexts are cancelled and `Serve` returns. Test: Task 16 `TestDrainTimeoutCancels`.
- A handler that keeps a goroutine sending progress after it returned must not write anything after the response. Test: Task 11 `TestNotifyAfterDone`, Task 18 `TestNoWriteAfterResponse`.
- Non-ASCII tool names and resource URIs travel in `Mcp-Name` base64 encoded and are compared after decoding on both sides. Test: Task 18 `TestHeaderMismatch` row `non-ascii name`, Task 19 `TestBase64Name`.

### Task 5: JSON Schema inference and basic validation

**Files:**
- Create: `jsonschema/infer.go`, `jsonschema/tags.go`, `jsonschema/validate.go`, `jsonschema/infer_test.go`, `jsonschema/validate_test.go`, `jsonschema/testdata/*.golden.json`

**Interfaces:**
- Produces:

```go
package jsonschema

func For[T any]() (json.RawMessage, error)
func ForType(t reflect.Type) (json.RawMessage, error)

type Validator interface{ Compile(schema json.RawMessage) (Schema, error) }
type Schema interface{ Validate(instance json.RawMessage) error } // returns *ValidationError or errors.Join of them
type ValidationError struct{ Path, Message string }              // Error(): "<path>: <message>", path in JSON Pointer form, "" for the root
func Basic(opts ...BasicOption) Validator
func MaxDepth(n int) BasicOption   // default 64: deeper schemas fail Compile, deeper instances fail Validate
func MaxSteps(n int) BasicOption   // default 1_000_000 keyword evaluations per Validate, then a ValidationError at the root

type SchemaProvider interface{ MCPSchema() json.RawMessage } // ForType returns this schema when the type or its pointer implements it
```

Inference rules:
- A struct becomes `type: object` with `properties` named by `json` tags (skip `-`, follow embedded structs as encoding/json does). `required` lists fields without `omitempty` or `omitzero`, sorted. `additionalProperties: false`.
- string gives `string`, bool gives `boolean`, ints give `integer`, uints give `integer` with `minimum: 0`, floats give `number`.
- `[]T` and arrays give `array` with `items`. `map[string]T` gives `object` with `additionalProperties`. Pointers use their element type.
- As built: whatever `encoding/json` writes for a value passes its own schema.
  - A pointer field is optional and also accepts `null`.
  - Slices, maps and `[]byte` (`string` with `contentEncoding: base64`) accept `null` too, because a nil one is written as `null`.
  - Fixed arrays carry `minItems` and `maxItems`.
  - A field with the `,string` option is a string.
  - Types implementing `json.Marshaler` give `{}`, and `encoding.TextMarshaler` gives `string`.
  - Embedded structs follow `encoding/json`: the shallowest name wins, then a tagged one, and other ties drop the name. Fields under an embedded pointer are optional.

- `time.Time` gives `string` with `format: date-time`. `json.RawMessage` and `any` give `{}`.
- A recursive type goes into `$defs` under its Go type name and is referenced with `$ref: "#/$defs/<Name>"`.
- Tag `jsonschema:"description=...,enum=a|b,minimum=0,maximum=10,minLength=1,maxLength=5,pattern=^a,format=uri,default=x"` sets those keywords. A comma inside `description` is written as `\,`.
- The output has stable key order so golden files never churn.

The basic validator supports `type` (also arrays of types), `properties`, `required`, `additionalProperties` (bool or schema), `items`, `enum`, `const`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength` (counted in runes), `pattern` (RE2, a bad pattern fails `Compile`), `minItems`, `maxItems`, and `$ref` to `#/$defs/...`. A `$ref` that is not a local `#/` pointer fails `Compile`, so no network fetch can ever happen. Unknown keywords are ignored; the package doc says `jsonschema/full` (v0.4) covers the rest. Numbers are compared as exact decimals (`json.Number` parsed into `big.Rat`), never as float64.
